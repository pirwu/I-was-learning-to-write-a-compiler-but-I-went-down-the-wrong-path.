================================================================================
          LOOM VIRTUAL MACHINE (LVM) — BYTECODE SPECIFICATION v1.0
================================================================================

1. ARCHITECTURE OVERVIEW
================================================================================

The LVM is a stack-based virtual machine with strict runtime type enforcement.

Memory regions:
  - Operand Stack:   temporary values during expression evaluation
  - Call Stack:      function frames (local variables + return address)
  - Heap:            objects, arrays, strings, closures, iterators
  - Constant Pool:   literals, class references, function references, strings
  - Global Table:    global variables indexed by u16

Value representation (tagged union, 16 bytes aligned):
  +-----------+---------------------------+
  | tag (u8)  | payload (u64 / f64 / ptr) |
  +-----------+---------------------------+
  Tags: 0=INT  1=DOUBLE  2=STR  3=CHAR  4=BOOL
        5=OBJ  6=ARRAY  7=DICT  8=FUNC  9=CLOSURE
        10=ITER 11=NULL 12=VOID 13=TYPE 14=RANGE

Instruction format:
  [ OPCODE : u8 ] [ OPERAND : 0 | 1 | 2 | 4 | 8 bytes ]

Operand size suffixes in this document:
  _u8   = 1 byte unsigned   (local index, arg count, flags)
  _u16  = 2 bytes unsigned  (constant pool index, jump offset)
  _i16  = 2 bytes signed    (relative jump offset)
  _u32  = 4 bytes unsigned  (global index, large offset)
  _i64  = 8 bytes signed    (inline integer literal)
  _f64  = 8 bytes float     (inline double literal)

------------------------------------------------------------------------
2.1  STACK OPERATIONS  (0x00 – 0x0F)
------------------------------------------------------------------------
  0x00  NOP                         no operation
  0x01  PUSH_CONST      _u16        push constant pool[index]
  0x02  PUSH_INT        _i64        push inline 64-bit integer
  0x03  PUSH_DOUBLE     _f64        push inline 64-bit float
  0x04  PUSH_STR        _u16        push string from constant pool
  0x05  PUSH_CHAR       _u8         push single character (ASCII/UTF-8 code)
  0x06  PUSH_TRUE                   push bool true
  0x07  PUSH_FALSE                  push bool false
  0x08  PUSH_NULL                   push null value
  0x09  POP                         discard top of stack
  0x0A  DUP                         duplicate top of stack
  0x0B  DUP2                        duplicate top two values
  0x0C  SWAP                        swap top two values
  0x0D  ROT3                        rotate top three: [a b c] -> [b c a]
  0x0E  OVER                        copy second value to top: [a b] -> [a b a]
  0x0F  POP_N           _u8         pop N values from stack

3. CONSTANT POOL FORMAT
================================================================================

The constant pool is an array of tagged entries stored at the beginning of
each compiled module / function object.

  Entry format:
    [ tag : u8 ] [ length : u32 ] [ data : length bytes ]

  Tags:
    0x01  INT_CONST       data = i64
    0x02  DOUBLE_CONST    data = f64
    0x03  STR_CONST       data = UTF-8 bytes
    0x04  CHAR_CONST      data = u32 (Unicode codepoint)
    0x05  FUNC_REF        data = u32 (bytecode offset)
    0x06  CLASS_REF       data = u32 (class descriptor offset)
    0x07  TYPE_DESC       data = type descriptor bytes
    0x08  MODULE_NAME     data = UTF-8 bytes


4. FUNCTION FRAME LAYOUT
================================================================================

  +----------------------------+
  | return address (u64)       |
  | previous frame pointer     |
  | local[0]  (LoomValue)      |  ← first parameter
  | local[1]  (LoomValue)      |
  | ...                        |
  | local[N]  (LoomValue)      |  ← last local variable
  +----------------------------+
  | operand stack grows up →   |
  +----------------------------+


5. COMPILATION EXAMPLES (LOOM SOURCE → BYTECODE)
================================================================================

------------------------------------------------------------------------
Example 1: Variable declaration + while loop (strict typing)
------------------------------------------------------------------------
  Source:
    var x : int = 10;
    var y : int = 0;
    while (x > y) {
        y += 1;
    }

  Bytecode:
    0000  LINE_INFO       1
    0005  PUSH_INT        10
    000E  STORE_LOCAL     0          # x = 10
    0010  LINE_INFO       2
    0015  PUSH_INT        0
    001E  STORE_LOCAL     1          # y = 0
    0020  LINE_INFO       3
    0025  SETUP_LOOP      +22        # loop end at 0047
    0028  LOAD_LOCAL      0          # push x
    002A  LOAD_LOCAL      1          # push y
    002C  CMP_GT                     # x > y
    002D  JUMP_IF_FALSE   +18        # exit loop → 0047
    0030  LINE_INFO       4
    0035  LOAD_LOCAL      1          # push y
    0037  PUSH_INT        1
    0040  ADD                        # y + 1
    0041  STORE_LOCAL     1          # y = y + 1
    0043  JUMP            -18        # back to 0028
    0046  POP_LOOP
    0047  HALT

------------------------------------------------------------------------
Example 2: Console I/O
------------------------------------------------------------------------
  Source:
    console.write("Name: ");
    var n : str = input();
    console.write(n);

  Bytecode:
    0000  PUSH_STR        0          # "Name: " from pool
    0003  CONSOLE_WRITE
    0004  INPUT_READ      0          # no prompt argument
    0006  STORE_LOCAL     0          # n = input()
    0008  LOAD_LOCAL      0          # push n
    000A  CONSOLE_WRITE

------------------------------------------------------------------------
Example 3: Function with strict return type
------------------------------------------------------------------------
  Source:
    function add(a : int, b : int) -> int {
        return a + b;
    }

  Bytecode (function body, offset 0 inside func object):
    0000  LOAD_LOCAL      0          # a
    0002  LOAD_LOCAL      1          # b
    0004  ADD
    0005  TYPE_CHECK      1          # assert result is int (pool[1] = INT type)
    0008  RETURN

------------------------------------------------------------------------
Example 4: For-loop with range (Rust-style ..)
------------------------------------------------------------------------
  Source:
    for (i in 1..5) {
        console.write(i);
    }

  Bytecode:
    0000  PUSH_INT        1
    0009  PUSH_INT        5
    0012  BUILD_RANGE     0          # exclusive (..)
    0014  GET_ITER
    0015  SETUP_LOOP      +16        # loop end at 0031
    0018  ITER_NEXT       +11        # if exhausted → 0031
    001B  STORE_LOCAL     0          # i = next value
    001D  LOAD_LOCAL      0
    001F  CONSOLE_WRITELN
    0020  JUMP            -8         # back to ITER_NEXT
    0023  POP_LOOP
    0024  ITER_CLOSE
    0025  HALT

------------------------------------------------------------------------
Example 5: Match expression
------------------------------------------------------------------------
  Source:
    match x {
        when 1 => console.write("one"),
        when _ => console.write("other")
    }

  Bytecode:
    0000  MATCH_START                # keep x on stack
    0001  DUP
    0002  MATCH_LITERAL   0          # compare with 1 (pool[0])
    0005  JUMP_IF_FALSE   +8         # skip to next arm
    0008  PUSH_STR        1          # "one"
    000B  CONSOLE_WRITE
    000C  JUMP            +8         # skip to MATCH_END
    000F  MATCH_BIND      0          # wildcard: bind to local 0 (or discard)
    0011  PUSH_STR        2          # "other"
    0014  CONSOLE_WRITE
    0015  MATCH_END

------------------------------------------------------------------------
Example 6: Class definition + instantiation
------------------------------------------------------------------------
  Source:
    class Animal {
        public name : str;
        constructor(n : str) {
            this.name = n;
        }
    }
    var a : Animal = new Animal("Cat");

  Bytecode:
    # --- class definition ---
    0000  DEFINE_CLASS    0          # "Animal" from pool
    0003  SET_ACCESS      0          # public
    0005  DEFINE_FIELD    1 2        # field "name" : str
    0009  DEFINE_METHOD   3 4        # method "constructor" → func_ref 4
    # --- constructor body (separate func object) ---
    0000  LOAD_SELF
    0001  LOAD_LOCAL      0          # n
    0003  STORE_ATTR      1          # this.name = n
    0006  RETURN_VOID
    # --- instantiation ---
    000C  NEW_OBJECT      0          # allocate Animal
    000F  PUSH_STR        5          # "Cat"
    0012  INVOKE_CTOR     1          # call constructor with 1 arg
    0014  STORE_LOCAL     0          # a = new Animal("Cat")

Example 7: Try / Except / Finally
------------------------------------------------------------------------
  Source:
    try {
        var x : int = 10 // 0;
    } except {
        console.write("error");
    } finally {
        console.write("done");
    }

  Bytecode:
    0000  SETUP_TRY       +14        # handler at 0014
    0003  PUSH_INT        10
    000C  PUSH_INT        0
    0015  IDIV                       # 10 // 0  → throws DivisionByZero
    0016  STORE_LOCAL     0
    0018  POP_TRY

    # --- except ---
    001C  POP_EXCEPT
    001D  PUSH_STR        0          # "error"
    0020  CONSOLE_WRITE

    0021  SETUP_FINALLY   +6
    0024  PUSH_STR        1          # "done"
    0027  CONSOLE_WRITE
    0028  POP_FINALLY

6. COMPOUND ASSIGNMENT DESUGARING
================================================================================

Compound assignments have NO dedicated opcodes. The compiler desugars them:

  Source            Desugared to              Bytecode pattern
  ──────────────    ──────────────────────    ──────────────────────────
  x += 1            x = x + 1                 LOAD x, PUSH 1, ADD, STORE x
  x -= 1            x = x - 1                 LOAD x, PUSH 1, SUB, STORE x
  x *= 2            x = x * 2                 LOAD x, PUSH 2, MUL, STORE x
  x /= 2            x = x / 2                 LOAD x, PUSH 2, DIV, STORE x
  x //= 2           x = x // 2                LOAD x, PUSH 2, IDIV, STORE x
  x %= 3            x = x % 3                 LOAD x, PUSH 3, MOD, STORE x
  x **= 2           x = x ** 2                LOAD x, PUSH 2, POW, STORE x
  x &= mask         x = x & mask              LOAD x, LOAD mask, BIT_AND, STORE x
  x |= mask         x = x | mask              LOAD x, LOAD mask, BIT_OR, STORE x
  x ^= mask         x = x ^ mask              LOAD x, LOAD mask, BIT_XOR, STORE x
  x <<= 2           x = x << 2                LOAD x, PUSH 2, LSHIFT, STORE x
  x >>= 2           x = x >> 2                LOAD x, PUSH 2, RSHIFT, STORE x
  x++               x = x + 1                 INC_LOCAL index  (shortcut)
  x--               x = x - 1                 DEC_LOCAL index  (shortcut)

8. STRICT TYPING ENFORCEMENT SUMMARY
================================================================================

  - DECLARE_VAR / DECLARE_CONST embed type descriptors in the constant pool.
  - TYPE_CHECK opcode validates runtime type after every function return
    and every explicit cast.
  - CAST opcode performs strict narrowing/widening; throws TypeError on
    incompatible types.
  - INSTANCE_OF checks class hierarchy at runtime.
  - All arithmetic opcodes (ADD, SUB, MUL, DIV, IDIV, MOD, POW) verify
    that both operands share a compatible numeric type; implicit widening
    from int → double is allowed, all other mismatches throw TypeError.
  - String concatenation (ADD with str operands or CONCAT) is the only
    allowed mixed-type arithmetic.
